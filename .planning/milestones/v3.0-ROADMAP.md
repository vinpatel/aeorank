## Phase 17 — Launch blockers

**Goal:** The repository survives inspection by a hostile technical evaluator on launch day.

**Requirements:** SEC-01, SEC-02, SEC-03, SEC-04, SEC-05, SEC-06

**Why first:** 242 open Dependabot alerts (7 critical, 101 high) is 3× the 80 recorded in
April — the debt compounded while development was paused. `LAUNCH.md` currently claims
"675 tests, 0 Dependabot / CodeQL alerts" in the drafted Show HN body; that is false today
and HN would find it within minutes. No amount of parity work survives that.

**Success criteria:**
1. `gh api .../dependabot/alerts?state=open` returns zero critical and zero high severities.
2. A reader can pick any number in LAUNCH.md, README, or the marketing site and trace it to a command that produces it.
3. CI emits one test count; docs and badges read from that, not from hand-edits.
4. `fix/scan-callback-url` is merged to main with the Supabase migration applied and the keep-alive cron live.
5. aeorank.dev, docs.aeorank.dev, and app.aeorank.dev all load, and the Action resolves on the GitHub Marketplace.

## Phase 18 — Public API

**Goal:** The $99 API tier stops being a pricing-page promise and becomes a product.

**Requirements:** API-01, API-02, API-03, API-04, API-05, API-06, API-07

**Why second:** All five competitors ship an API. PROJECT.md has advertised a $99 API tier
since v1.0 and the endpoint set does not exist — `apps/web/app/api/*` is entirely internal,
session-authenticated dashboard plumbing. This is the only gap on the list that is
simultaneously a competitive gap and an unfulfilled revenue promise.

**Success criteria:**
1. A user can mint a scoped key in the dashboard and revoke it, and revocation takes effect immediately.
2. `curl` with a bearer key can start a scan, poll it, and read back score, grade, and all 36 dimensions.
3. All 9 generated files are retrievable per scan over the API.
4. Exceeding a plan's quota returns 429 with quota headers, and the limit matches the tier.
5. The docs site serves an OpenAPI spec that validates, plus a reference page.

## Phase 19 — MCP server

**Goal:** An AI coding agent can scan and fix a site without a human opening the dashboard.

**Requirements:** MCP-01, MCP-02, MCP-03

**Why here:** Smallest phase on the roadmap and the highest identity fit — Otterly is the
only competitor with an MCP surface, and their audience is marketers while ours is
developers already working inside agents. Depends on Phase 18's auth and handlers, so it is
mostly a protocol wrapper over work already done.

**Success criteria:**
1. An agent in Claude Code can call a scan tool against a URL and receive a structured score.
2. Scan results and generated files are exposed as MCP resources the agent can read.
3. Install docs cover Claude Code, Claude Desktop, and generic clients, and a fresh install works from those docs alone.

## Phase 20 — Crawler analytics

**Goal:** Users can see which AI bots actually fetch their pages, not just whether the rules permit it.

**Requirements:** CRAWL-01, CRAWL-02, CRAWL-03, CRAWL-04

**Why here:** Four of five competitors shipped this, and three of them shipped it since
April — it went from a Profound-only feature to table stakes in one quarter. It also fits
the deterministic story cleanly: log analysis is measurement, not LLM inference.

**Success criteria:**
1. A user can connect Vercel or Cloudflare logs to a site in the dashboard.
2. The dashboard charts AI crawler hits by bot over time.
3. Non-200 responses served to AI bots are surfaced as errors with the affected URLs.
4. A user can compare pages AI crawlers fetch against pages that exist in the sitemap.

## Phase 21 — Alerts

**Goal:** A regression reaches the user without them logging in.

**Requirements:** ALERT-01, ALERT-02, ALERT-03, ALERT-04

**Why here:** Depends on scan history (exists) and crawler data (Phase 20). Cheap once both
are in place, and it converts the product from something you visit into something that
watches for you — the main reason monitoring tools retain.

**Success criteria:**
1. A score drop past a user-set threshold fires an alert.
2. A newly blocked AI crawler or robots.txt regression fires an alert.
3. A generated file disappearing or going stale fires an alert.
4. Each alert can be routed to email, Slack, or a webhook, and delivery is verifiable.

---

## Phase 22 — Reports & exports

**Goal:** Scan data leaves the product in the formats buyers actually ask for.

**Requirements:** RPT-01, RPT-02, RPT-03, RPT-04

**Why here:** Every competitor exports CSV; we ship a ZIP of generated files and nothing
else. This is the most common gap to surface in a side-by-side evaluation and it is
low-risk work.

**Success criteria:**
1. CSV export of a scan opens correctly in a spreadsheet with one row per dimension.
2. JSON export is schema-stable and matches the API's shape.
3. A PDF report renders the score, pillar breakdown, and fix list, and is shareable by link.
4. A user can schedule a report and receive it on the chosen cadence.

---

## Phase 23 — Integrations

**Goal:** AEOrank installs where the site already lives.

**Requirements:** CONN-01, CONN-02, CONN-03, CONN-04

**Why here:** Needs the API (18) and crawler ingestion (20) to be meaningful. GSC in
particular closes the loop that competitors sell hard — correlating AEO score against
actual AI-referral traffic.

**Success criteria:**
1. A user can OAuth into Google Search Console and see AI-referral traffic beside AEO score.
2. GA4 connects and reports traffic as a source.
3. The Vercel integration installs AEOrank against a project without leaving Vercel.
4. The Cloudflare integration installs against a zone without leaving Cloudflare.

---

## Phase 24 — Geo & language

**Goal:** Scanning is not implicitly US-English-only.

**Requirements:** GEO-01, GEO-02

**Why here:** Three of five competitors sell multi-region and multi-language explicitly.
Lower urgency than the surfaces above, but it currently produces silently wrong scores for
non-English sites, which is worse than a missing feature.

**Success criteria:**
1. A user can select a scan region and the scan demonstrably originates there.
2. A non-English site is not penalised by any of the 36 criteria for being non-English, verified against a fixture set.

---

## Phase 25 — Defend the moat

**Goal:** The ground nobody else holds stays uncontested.

**Requirements:** DEF-01, DEF-02, DEF-03

**Why last:** Needs the crawler identification work from Phase 20 to serve variants
correctly. Scrunch's AXP and Otterly's GEO URL audits are the first competitor moves into
AEOrank's territory; this is the answer to both, plus finally shipping the scoreboard that
has sat unpublished in a JSON file since April.

**Success criteria:**
1. Edge middleware serves an AI-optimised variant to identified AI crawlers and the normal page to humans, verified by user-agent test.
2. A reproducible benchmark comparing AEOrank audit depth to Otterly's GEO URL audit is published.
3. The 100-funded-startup scoreboard is live at a public URL and linkable from the marketing site.
