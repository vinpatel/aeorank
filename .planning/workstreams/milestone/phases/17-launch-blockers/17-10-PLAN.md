Protect `refs/heads/main` using a **repository ruleset**, not classic branch protection.
Classic protection cannot grant a bypass to GitHub Actions, and D-04 requires the three bot
workflows to keep pushing directly to main without being converted to PRs.

`gh api -X POST repos/vinpatel/aeorank/rulesets` with:
- `target: "branch"`, `enforcement: "active"`
- `conditions.ref_name.include: ["~DEFAULT_BRANCH"]`
- rules: `non_fast_forward`, `deletion`, and `required_status_checks` listing exactly
  `verify` and `audit` as required contexts, with a strict-required-status-checks policy
  appropriate to a solo repo
- `bypass_actors`: the GitHub Actions integration ONLY — `actor_type: "Integration"` with
  the GitHub Actions app id, `bypass_mode: "always"`. Resolve the app id rather than guessing
  it, e.g. from `gh api repos/vinpatel/aeorank/installation` or the ruleset UI's suggested
  actor list.

Hard prohibitions:
- Do NOT add `actor_type: "RepositoryRole"` with the admin role as a bypass actor (unless the
  Task 2 checkpoint explicitly chose it). On a solo repository the admin is the only human who
  pushes, so an always-on admin bypass makes "main is protected" false by construction and
  makes the direct-push rejection criterion below unachievable — the executing agent pushes
  with owner credentials and would sail straight through the ruleset it just created. The
  emergency path is editing or deleting the ruleset in Settings -> Rules -> Rulesets, which
  an admin can do at any time and which leaves an audit trail.
- Do NOT add `lint` to the required contexts. It is `continue-on-error` and reports roughly
  364 real violations; requiring it makes the repository permanently unmergeable. Plan 17-03
  Task 1 records this decision and the measured count.
- Do NOT add a `pull_request` rule requiring reviews — this is a solo repository and a
  mandatory-review rule with no second reviewer would deadlock it.
- Do NOT weaken `enforcement` to `"evaluate"` to make a failing verification pass. If a bot
  workflow fails on a protected-branch error, the bypass actor is wrong — fix the actor.

**Protection is real.** On a throwaway branch, create a commit that would fail the checks
