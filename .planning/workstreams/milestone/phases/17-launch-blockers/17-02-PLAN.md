Hard prohibitions:
- Do NOT remove `astro` from `packages/astro` — `src/index.ts` has
  `import type { AstroIntegration } from "astro"`, a real import.
- Do NOT remove `@nuxt/kit` from `packages/nuxt` (imported by `src/module.ts`) or `h3`
  (imported by `src/runtime/server.ts`). Plan 17-01 added the `h3` declaration precisely
  because that import was previously unsatisfied and broke `pnpm typecheck`; removing it
  re-breaks the gate. `h3` is expected to survive Lever A and remain in the tree — the root
  override already pins it at `>=1.15.9`, so it is accounted for and is not a shortfall in
  the measured alert drop.
- Do NOT touch any `peerDependencies` or `peerDependenciesMeta` block anywhere. Peers are
  the consumer contract for the published `@aeorank/next` and `@aeorank/nuxt` packages and
  do not cause installs. `pnpm remove` will not touch them; do not touch them by hand either.
- Do NOT treat `tsup.config.ts` `external:` entries as evidence of a dependency — they are
  bundler directives and do not require the package to be installed. This is exactly why
  `next`, `@remix-run/*`, `@sveltejs/kit`, and `@docusaurus/types` are removable.

Then run the hard gate: `pnpm install && pnpm build && pnpm typecheck && pnpm test`.

failures; if `pnpm typecheck` reports errors in `packages/cli`, `packages/nuxt/src/runtime`,

rather than attributing it to a removal.

untyped `eleventyConfig` parameter), restore that ONE devDependency and re-run the gate.
Do not abandon the lever because one package needs its declaration back — record which one
