## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vercel Cron -> `/api/cron/keep-alive` | Unauthenticated internet traffic can reach the route; only the shared secret distinguishes the scheduler |
| Application -> Supabase (`sites`, `scans`) | Row-level security separates users; the migration runs as a privileged role that bypasses RLS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Spoofing | `apps/web/app/api/cron/keep-alive/route.ts` | mitigate | Route requires `Authorization: Bearer $CRON_SECRET` and fails closed with 500 when the secret is unset; already covered by 4 tests in `route.test.ts` |
| T-17-02 | Tampering | `supabase/migrations/0001_sites_unique_user_id_url.sql` | mitigate | Migration issues `DELETE FROM sites`; blocking human checkpoint requires a snapshot and a pre-flight count before it runs, and re-points `scans.site_id` before deleting so the cascade never fires |
| T-17-03 | Elevation of Privilege | Supabase SQL Editor session | accept | Migration must run as the privileged role to bypass RLS; scoped to a single one-off DDL statement executed by the repo owner |
| T-17-04 | Information Disclosure | `CRON_SECRET` | mitigate | Stored only as a Vercel environment variable, never committed; the checkpoint asks the user to confirm presence, never to paste the value |
| T-17-SC | Tampering | npm/pnpm installs | accept | This plan installs no new packages — `pnpm install --frozen-lockfile` only restores the existing lockfile. RESEARCH.md `## Package Legitimacy Audit` records zero new package names for this phase |
